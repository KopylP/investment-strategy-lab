# Виправлення Strategy Builder — 6 листопада 2026

Закрито дев'ять помилок із [аудиту](strategy-builder-audit-2026-11-06.md). Перелік майбутніх аналітичних можливостей з аудиту — out-of-sample, walk-forward, дослідження параметрів, фундаментальні дані тощо — залишається окремим розвитком продукту.

## Реалізовані зміни

| № | Помилка | Результат |
|---|---|---|
| 1 | Недостатня історія | Python оголошує `historyBars` у перевірці параметрів. До кількості спостережень входять індикатори, вікна перетинів, кореляції й ваг. .NET завантажує відповідне календарне вікно із запасом; прогрів бектесту використовує оголошену кількість спостережень. Формули індикаторів залишаються в Python. |
| 2 | NOT дозволяв дію без даних | Результат умови має ознаку `known`. NOT зберігає невідомість. ALL з відомим False — False; ANY з відомим True — True; в інших невизначених випадках результат невідомий і не дозволяє дію. |
| 3 | Кореляція 20–59 днів | Мінімум спостережень узгоджений із вибраним вікном. Недостатня або невизначена кореляція не обходить ліміт: кандидат отримує явну причину відмови. |
| 4 | Різні валюти собівартості й цін | Бектест передає валюту оцінки. Для утримуваних позицій backend додає `valuationClose` у валюті портфеля; Python використовує цей ряд для стопів та вартості позицій. Індикатори продовжують використовувати початковий `adjustedClose` у валюті лістингу. Відсутній або застарілий FX дає помилку замість порівняння різних валют. |
| 5 | Розклад втрачав день | Бектест зберігає день місяця/тижня. Для короткого місяця бере останній день; свято переносить дію на наступну сесію з фактичними котируваннями фондів. Торгівля лише бенчмарком не споживає розклад закритого ринку фондів. |
| 6 | Rebalance пропускав risk review | Обидві події виконуються. Стоп замінює накази для відповідної позиції повним виходом; інші накази зберігаються. Порожня перевірка ризику не стирає ребалансування. Лічильник виходів збільшується лише після фактичного продажу. |
| 7 | Перетин лише крайніх точок | Перевіряються всі сусідні пари в останніх N сесіях. Пропуски даних у цьому вікні дають невідомий результат. |
| 8 | Угоди за застарілою ціною | Ціни оцінки відокремлені від цін виконання. Наказ виконується тільки за фактичним котируванням дня; очікує коротку перерву торгів і втрачає чинність через 7 календарних днів. Довільно пізня ціна не виконує старий наказ. |
| 9 | Перевернутий діапазон | `low > high` відхиляється локально в графі й через engine API. Помилка прив'язана до відповідного вузла, зокрема у вкладених умовах. |

## Зафіксовані правила

- Денний бектест підтримує звіти на **20:00**, від щоденних до квартальних. Hourly та інший час явно відхиляються, оскільки потребують внутрішньоденних даних. Підказка є в редакторі розкладу, а помилка локалізована. Це обмеження симуляції; живі розклади не переписуються.
- Перший придатний день після прогріву ініціалізує портфель. Подальші рішення дотримуються розкладу.
- Вікно перетину означає **наявність хоча б одного перетину** заданого напрямку за останні N сесій. Воно не вимагає, щоб сьогодні індикатор усе ще залишався з того самого боку рівня.
- Котирування для правил вважається застарілим після **7 календарних днів**. Це допускає вихідні й короткі свята, але блокує індикатори на давно припиненій історії. Перевірка ризику утримуваної позиції без свіжої ціни завершується явною помилкою.
- Для оцінки вартості бектест може зберігати останню відому ціну. Це не дає права виконувати за нею угоду. Автоматичну ціну примусової ліквідації при делістингу система не вигадує.
- Грошові ряди бектесту й собівартість його лотів узгоджені у валюті портфеля. Сигнали momentum/trend залишаються у валюті лістингу. Додаткові поля контракту необов'язкові; для контексту без окремого грошового ряду зберігається попередня поведінка.

Збірка backend попереджає про конфігурацію Aspire CLI bundle; frontend має наявні попередження про невикористані pipes, CommonJS і CSS budget. Вони не перешкодили збіркам. Повний UI/API/Postgres E2E та прогін із живими біржовими даними не виконувалися.
